# IAPT-ARI2201: Malta Road Recovery — Submission Notes

## Overview

This is a complete, runnable end-to-end pipeline:

1. **Manual counts** (field observations) → **Demand pulses** → **Simulation**
2. **Simulation** (cell-transmission engine) → **Synthetic ground truth**
3. **Ground truth** → **RandomForest training** → **Recovery-time predictor**

## Quick Start

```bash
# Install dependencies (one-time)
pip install -r requirements.txt

# Launch the interactive CLI menu
cd malta-road-recovery
python main.py

# Or test individual scripts:
python data_processing/manual_to_pulse.py --all
python simulation/calibrator.py
python ml/train_model.py
python ml/predict.py
```

## Expected Behaviour

### CLI Menu (Option by Option)

**[1] View a Single Scenario (Closure Preview)**
- Drills: Direction → Slot → Horizon → Variant (all_open / 1_lane_closed / 2_lanes_closed)
- Output: Live Matplotlib animation showing heatmap + vehicle particles

**[2] View a Scenario (Closure + Opening Recovery)**
- Drills: Direction → Slot → Horizon → Transition (2→1, 2→0, 1→0, etc.)
- Output: Live animation showing both ACCIDENT and RECOVERY phases

**[3] RUN STANDARD BATCH**
- Generates 162 scenarios (1 seed, seed=42)
- Writes playback JSON/CSV/particles to `data/synthetic/scenarios/<H>s/`
- Writes 162-row `master_traffic_features.csv`
- Takes ~5 minutes

**[4] RUN ML FACTORY BATCH**
- Generates 810 scenarios (162 × 5 seeds)
- Appends 5 rows per scenario to `master_traffic_features.csv`
- Final: 810 rows (used for RandomForest training)
- Takes ~5 minutes

**[5] TRAIN ML MODEL**
- Loads 810-row dataset
- 80/20 train/test split (≈648 training rows)
- GridSearchCV over n_estimators, max_depth, min_samples_split
- Outputs: R², MAE, feature importances, serialized model
- Takes ~10–15 seconds

**[6] PREDICT RECOVERY**
- Interactive dashboard
- Select road, time slot, incident duration, transition type
- Returns predicted recovery time in seconds and minutes
- Baseline conditions extracted from precomputed dataset

## Key Design Decisions

### Why Custom Engine (not SUMO)?

- **Transparency**: Every physics equation is documented and auditable
- **Portability**: No SUMO binaries, no X11/XQuartz dependencies
- **Speed**: Runs on any laptop, any OS, zero overhead install

### Why Particle-List State?

- Enables per-cell speed gradients (free flow → queue)
- Tracks cumulative delay per vehicle for accurate recovery metrics
- Natural merge bottleneck at competing inflows

### Why GridSearchCV (not AutoML)?

- Small training set (810 rows) → risk of overfitting
- Conservative parameter ranges prevent memorization
- Interpretable feature importance output (critical for dissertation)

### Why Linear Extrapolation for Censored Recovery?

- If vehicle doesn't fully clear by end of horizon, fit a slope to final 120s
- Project when network speed crosses threshold (60 kph Regional, 45 kph Valley)
- Cap at 3600s per config
- Avoids null predictions and provides reasonable upper bounds

## Known Limitations

1. **Static networks**: Road geometry is hardcoded, not parsed from OSM.
2. **Four corridors only**: Extensible but currently Malta-specific.
3. **Daytime-only**: No night-time demand profile.
4. **Recovery ceiling**: Capped at 3600s; longer incidents extrapolated.
5. **No external events**: Assumes incident is the only closure; doesn't model cascading failures.
